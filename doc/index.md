**Preface**

As an engineer, I am constantly aware of the limited accuracy by which we are surrounded in reality.
Arbitrary precision CAN be achieved, but only at great cost (which is usually not worth the effort).

This is maybe one reason - and hopefully not an excuse - why this work is not aiming at perfection.
Instead, I want to be open about the many flaws the presented framework has.

Some things just don't work yet.
Others, may be severe problems, I have probably never even thought about.
There is so much to know, yet so much that I still don't understand and maybe never will.

But, the software that has been developed for this work also contains some good approximations of reality.
The early decision to modularize the framework has been key in achieving this.
Separating functionality and thinking about interfaces allows for an efficient develpment, testing, and exchange of connected logic.
Furthermore, this facilitates a system setup for incremental improvement.
If some issue or lack of feature turns out to be relevant, it can be fixed without disturbing the state of other aspects of the framework.

Being able to adapt to different standards also enables a better communication with the (scientific) environment.
In general, the better modules were developed as a consequence of human interaction for which I am very thankful.
So many things, I could take for granted, because others went the "extra mile".
And learning from the enthusiasm of others is a shortcut to understanding like no other.

Hopefully the future will allow me to continue developing the software we have developed.
But kowing where to *stop* is an art that takes a life to master.
For now, this is what I've got.
